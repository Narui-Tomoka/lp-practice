
/* CSS→scss作業手順 */
/* HTMLファイル開きclass名をBEM記法に直す
（複数個所に同じクラス名を使うことも多いのでHTML内で検索してctrl shift L で一括選択する）
（&で紐づけした効率的できれいなコードにするため） */
/* 直す前のclass名をstyle.cssで検索し、該当classを新しい名称に直す */
/* あらかじめ用意した_scssファイルのどこに記述しなおせばよいか考え、記述場所を移す */
/* 値を変数に格納できそうであれば_variables.scssに定義しておいて@useで読み込む */

・一か所でもパス指定ができていないとエラーが出てコンパイルされない
エラーが出た場所は赤文字で^^^^^^^^^^^が出たところの下に表示されていた。

変更前のクラス名と変更後をうっかり忘れる恐れもあるので、
元のクラスを残したままHTMLに新しいクラス名を書く
→元のクラス名を作業中のCSSファイルで検索して、該当部分に新しいクラス名を追加
→派生した新しいクラス名の部分にも追記し終わったらHTMLとCSSのもとのクラスを消す
→ブラウザでHTMLを更新して表示が崩れないか確認
という手順を取ると安心

同じクラス名を修正することからctrl + shift + L で同じ単語を一括選択したほうが間違えなくて早い

as ○○ というニックネームはつけたほうが良い
名称が長いと書くのが面倒なだけでなく、タイプミスも誘発する
エラーの原因になるだけでなく、スペルが長いと一文字ずつあっているか確認しないといけない気がする

HTMLを書く時点でclass名はちゃんとつけておく
練習では使わないからと第三章の段階ではaタグにクラスをつけていなかったが実装時はほぼ確実に必要になるため

同じセレクタに対しては、メディアクエリ記述は他のスタイルの後に書く
メディアクエリ記述の後に通常のスタイルを書いてしまうと上書きされてしまい、意図したスタイルが適用されない
今回の課題ではskillsの6つの画像の配置で以下のように書くべきだった。
【よい例】
&:nth-last-child(-n + 3) {
      // 最後から3つ
      margin-bottom: 0;
    }
    &:nth-child(3n) {
      // 3の倍数
      margin-right: 0;
      @include mix.mq(sp-tab) {
        margin-bottom: 80px;
      }
    }

しかし以下のように記述してしまったことで
margin-bottom: 80px; が上書きされてしまい、レイアウトが崩れてしまった。
修正箇所を探したり修正に時間がかかるので、最初からメディアクエリ記述は後で書くと覚えて置いたほうがいいと感じた。
【悪い例】
&:nth-child(3n) {
      // 3の倍数
      margin-right: 0;
      @include mix.mq(sp-tab) {
        margin-bottom: 80px;
      }
    }
    &:nth-last-child(-n + 3) {
      // 最後から3つ
      margin-bottom: 0;
    }
